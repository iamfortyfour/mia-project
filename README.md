# Mia — рабочее место и агент

**Mia** — это локальный интерфейс к бесплатному пулу LLM: один экран, в котором живёт агент **Мия**.
Внутри — мой роутер `llm-ladder` (`127.0.0.1:8787`), база знаний `agentdb` и журнал исходов.
Раньше называлось Nexus; переименовано 2026-09-16 решением пользователя.

## Состав

| Путь | Что |
|---|---|
| `bin/mia-web` | приложение: GTK3 + WebKit2, локальный HTTP только на `127.0.0.1`, отдаёт статику из `web/` и JSON-API |
| `bin/mia-launch` | открыть окно на 10-й рабочей области (биндинги `$mod+n`, `$mod+Shift+q`) |
| `bin/mia-tui` (`mia`) | терминальное рабочее место на случай ssh (curses, без зависимостей) |
| `bin/mia-panel` | компактная терминальная панель: лимиты, профили, метрики |
| `web/` | фронтенд: `index.html`, `style.css`, `app.js` — без сборки и без CDN |
| `docs/design.md` | дизайн-документ: что принято, почему, что отменено и какой из этого урок |
| `attic/` | отменённая 3D-сцена (`scene3d.js`, `probe3d.html`, `vendor/three`) и старый лаунчер `quota-window.sh.legacy` |

Симлинки в `~/.local/bin/` (`mia-web`, `mia-launch`, `mia-tui`, `mia-panel`, `mia`) ведут сюда,
поэтому биндинги i3 остаются короткими.

## Как запустить и проверить

```bash
~/.local/bin/mia-launch                      # или Win+N: откроет окно на области 10:Mia
pgrep -af 'bin/[m]ia-web'                    # процесс приложения
i3-msg -t get_tree | grep mia-web            # окно: класс mia-web, заголовок «Mia · панель»
ss -ltnp | grep mia-web                      # порт (только 127.0.0.1)
curl -s 127.0.0.1:<порт>/api/live | jq .pet   # состояние Мии: mood, fed_recent, hunger, уровень
```

Только сервер, без окна (удобно для проверки API):

```bash
~/dev/mia-project/bin/mia-web --server-only --port 8799
```

## Что на экране

Один экран без вкладок: **шапка** (имя, профиль, модель, квота, запросов, тема, часы, мини-портрет Мии
и фраза о её состоянии) → **чат** (вопросы к базе знаний и ответы Мии) → **живой поток** (таблица строк:
время · профиль · шаг · статус · мс · метка). Светлая тема — кнопка `◐`.

Правила интерфейса (действуют при любой правке): бумажный минимализм — волосяные линии вместо рамок,
никаких градиентов и теней; цвет кодирует только статус; цифры табличные; строки таблицы обновляются
на месте, чтобы ничего не прыгало.

## Мия (агент)

Кормится задачами. Её состояние считается на бэкенде из реальных метрик, а не декоративно:

| Показатель | Источник |
|---|---|
| сытость | успешные задачи за последний час (`outcomes`) |
| здоровье | ок-рейт моделей (`llm.ok_rate`) |
| скорость | p95 ответов |
| опыт, уровень | всего обслуженных запросов |
| настроение | комбинация + простой: `happy` / `idle` / `hungry` / `sick` / `sleep` |

Реакции на живой поток (SSE): `ok` — ест и радуется, `fail`/`empty` — грустнеет, `wait-decision` —
смотрит на часы, `squeeze` — сжимает пакет.

## API приложения

| Эндпоинт | Что отдаёт |
|---|---|
| `GET /api/live` | квоты, лимиты, журнал, состояние Мии (`pet`) |
| `GET /api/heavy` | доктор маршрутов, метрики, модели |
| `GET /api/flows?limit=N` | запросы с шагами (для таблицы потока) |
| `GET /api/stream` | SSE-прокси событий роутера |
| `GET /api/version` | отпечаток статики: страница сама перезагружается при правке файлов |
| `POST /api/ask {"q": …}` | поиск в базе знаний (тема → слова → смысл) |
| `POST /api/jslog` | ошибки JS страницы → stderr приложения |

## Зависимости

Никаких: Python 3 (stdlib) + `gi`/WebKit2GTK (уже в системе), фронтенд — чистый HTML/CSS/JS.
Сети приложение не требует: работает с локальным роутером и локальной базой.

## Чат: Мия отвечает сама (2026-09-16)

Чат больше не «поиск по базе», а разговор: `POST /api/chat {"q": …}` делает три вещи —
подтягивает фрагменты базы знаний (RAG, `db find`), берёт характер Мии из базы
(`brand:persona`) и отвечает через дешёвый простаивающий профиль роутера **`mia`**
(`preferModels`: qwen3.8-27b, gpt-oss-20b, GLM-5.3-Flash, gemini-flash-lite, ministral-8b, gemma-4-26b).

Ответ возвращает `answer` (её текст), `model` (кто отвечал), `sources` (ключи записей базы),
`found` и `lines` (сырые находки). **Если модель недоступна — чат не молчит:** фронтенд показывает
то, что нашлось в базе, и подписывает «модель не ответила». `/api/ask` остался как «только поиск».

Характер и правила Мии (кто она, тон, что нельзя выдумывать) живут в записи `brand:persona` —
меняются одной командой `db set brand:persona --body-file -`, без правки кода.
Проверка: `curl -s -X POST 127.0.0.1:8790/api/chat -H 'Content-Type: application/json' -d '{"q":"кто ты?"}'`.

## Идемпотентный запуск (2026-09-16)

Раньше повторное нажатие Win+N поднимало второе окно, а после переименования в баре висели
две «10» (пустая `10:Nexus` рядом с `10:Mia`). Теперь:

- `mia-launch` держит `flock` (два запуска одновременно невозможны), проверяет PID-файл
  `/tmp/mia-web.pid` и `pgrep`, после старта ждёт окно и фокусирует его;
- пустые области-остатки (`10:*`, `10`) переименовываются в актуальную `10:<имя>`;
- само приложение `mia-web` перед открытием окна спрашивает `GET /api/identity`: если на 8790
  уже отвечает **наш** сервер, второй экземпляр просто выходит;
- порт постоянный (`DEFAULT_PORT = 8790`, с `SO_REUSEADDR`), поэтому переписка и выбранная тема
  в `localStorage` не теряются между запусками.

Проверка: трижды подряд запустить `~/.local/bin/mia-launch` → должно остаться 1 процесс, 1 окно, 1 область «10».
