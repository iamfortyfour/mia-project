# Шаблон задачи для Мии

Промпт — это контракт, а не просьба. Ниже форма, в которой Мия ставит задачи:
её же системный промпт содержит этот шаблон, поэтому промпты не пишутся «как получится».

## Форма (все блоки обязательны)

```
РОЛЬ:         кем ты работаешь в этой задаче (например: инженер этого проекта).
КОНТЕКСТ:     3–7 фактов, чтобы не искать заново: пути к файлам, что уже есть,
              что уже проверено и чем, какие инструменты доступны.
ЗАДАЧА:       одно предложение + пункты «что именно сделать».
ОГРАНИЧЕНИЯ:  чего нельзя касаться (файлы/каталоги), режим доступа,
              запрет на sudo, «не менять существующие файлы».
КРИТЕРИИ:     проверяемые утверждения в виде «команда → ожидаемый результат».
ДОКАЗАТЕЛЬСТВА: что приложить в отчёт: вывод команд, путь к созданному файлу,
              JSON, скриншот. Отчёт «сделано» доказательством не считается.
ФОРМАТ:       ≤ N строк: списком или таблицей; отдельный раздел «что НЕ проверено».
САМОПРОВЕРКА: какие команды прогнать перед сдачей.
```

## Правила, без которых шаблон не работает

1. **Одна задача — один результат.** Один файл, один вопрос, одна проверка.
   Долгую работу разбивать на несколько задач, а не писать «сделай всё».
2. **Коротко по времени.** Ориентир — до 10 минут прогона. Всё, что дольше, разрезать:
   сегодня три делегации из пяти умерли именно на длинных задачах (таймаут, обрыв стрима).
3. **Доказательство — артефакт.** Путь к файлу, вывод команды, код возврата, JSON, скриншот.
   Слова «готово, всё хорошо» в отчёте не принимаются.
4. **Факты не выдумывать.** Не знаешь путь, число, имя ключа — сказать прямо «не знаю»
   и указать, где смотреть. Придуманные пути в задачах запрещены так же, как в ответах.
5. **Указывать, что читать, а не что «погуглить».** Конкретные файлы проекта:
   `~/dev/mia-project/...`, `~/docs/...`, `~/.config/llm-ladder/...`.
6. **Отдельно писать, чего НЕ делать:** не трогать `AGENTS.md` без разрешения,
   не править чужие конфиги, не коммитить в чужие репозитории, не менять systemd-юниты.
7. **Свободные модели.** Задача идёт на бесплатном профиле (`ladder/agent`, `ladder/code`,
   `ladder/vision`); платные (`paid`, `ladder/mixed`) не использовать без прямой команды.
8. **Режим доступа — в задаче.** `read` (только чтение), `edit` (правка в разрешённых
   каталогах), `full` (всё, кроме sudo). Режим фиксируется на момент старта.

## Пример (короткий, по делу)

```
РОЛЬ: инженер проекта Mia.
КОНТЕКСТ: приложение — ~/dev/mia-project/bin/mia-web (Python, GTK+WebKit), порт 8790.
  Страница: ~/dev/mia-project/web/{index.html,style.css,app.js}. Роутер: 127.0.0.1:8787.
ЗАДАЧА: добавить в панель задач свитч режима доступа с тремя значениями (read/edit/full),
  состояние хранить в ~/dev/mia-project/tasks/settings.json.
ОГРАНИЧЕНИЯ: не менять логику чата и таблицы потока; не трогать ~/.config/i3.
КРИТЕРИИ: `curl -s 127.0.0.1:8790/api/settings` → JSON с полем mode;
  переключение в UI меняет файл settings.json.
ДОКАЗАТЕЛЬСТВА: вывод curl до и после переключения, содержимое settings.json.
ФОРМАТ: ≤ 12 строк.
САМОПРОВЕРКА: node --check app.js; grep -c 'mode' style.css; curl /api/settings.
```

## Чего в промптах быть не должно

- «Сделай красиво», «придумай что-нибудь» — без критерия это не задача, а пожелание.
- Простыни на 3 экрана: контекст важнее объёма, 3–7 фактов достаточно.
- Просьб «проверь себя» без указания, чем именно проверять.
- Секретов и ключей: задача не должна содержать паролей и токенов — их вообще не должно быть в текстах.
